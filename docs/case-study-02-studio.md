# Case study 02 — Prototyping with a system in the loop

## Overview

The prototype studio lets visitors choose a team operations task, adjust requirements, and try a working interface built from approved patterns. It shows how a small system can speed up exploration while keeping design intent visible.

## The challenge

Rapid prototypes often become disposable one-offs. I wanted to show how an agent-assisted workflow could start from reusable components and explain why a particular pattern was chosen.

## My approach

I used the same Button, Text Field, Checkbox, and Alert components from the shared system. Visitors can switch between invitation and notification tasks, compare inline feedback with a page banner, and trigger success and error states. Brief guidance appears beside the prototype.

## Working with Codex

Codex implemented the interactive prototype from the system specification. I reviewed the copy, component placement, and recovery behaviour, then used desktop and mobile browser checks to verify the main journey. The first release assembles prepared patterns; it does not generate a new screen on demand.

## Outcome and next step

The studio gives visitors a concrete way to see system reuse rather than a static component gallery. Later, a live agent could assemble patterns from a richer brief while retaining the same human review points.
